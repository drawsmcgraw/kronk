## Headline

Home Assistant is six monthly releases behind: `2026.5.4` to `2026.11.2`. No release body or blog post from 2026.6.0 to 2026.11.2 mentions the Ollama integration, but the "All changes" lists (not read) carry six Ollama changes (corrections above). The known risks: hassil (the sentence matcher) goes from 3.5.0 to 3.12.1, the 2026.11 entity-name change touches `friendly_name`, which tool_service reads for players, and HA's bundled Music Assistant client must still talk to the pinned MA beta. M8 does not need the upgrade. M15 gains conveniences, not prerequisites. Proposed: Home Assistant first, in a window Drew declares after audio capture ends (2026-12-01), through `docs/runbooks/major-upgrade.md`.

Everything else with a major release: Grafana 13.3.1, LiteLLM v1.110.0 (22 minor lines ahead), Piper 2.5.4, nginx (the pin floats on a 1.29 mainline that gets no more patches), llama.cpp b12498, wyoming-faster-whisper 3.9.0, and 30 Python packages (across the three lockfiles) with newer minor or major releases. Nothing was upgraded.

## Home Assistant 2026.5.4 to 2026.11.2: what the build read

Sources, read 2026-11-18: the GitHub release bodies of every release from 2026.6.0 to 2026.11.2 (`api.github.com/repos/home-assistant/core/releases`), and the six release blog posts linked from the monthly `.0` releases (`www.home-assistant.io/blog/…/release-20266/` to `release-202611/`), including each post's "Backward-incompatible changes" section. Release notes do not list dependency bumps inside the monthly releases (those are in each post's linked "All changes" list, which was not read), so library versions below are what the patch notes say, not a full list.

### What M8 (streamed speech) would gain

Little. HA `2026.5.4` already streams TTS once a reply passes 60 characters (plan, M8 verification), and that is what Kronk uses. The only change on that path in six months of notes is a fix: 2026.6.2, "Mitigate TTS ResultStream leak in pipeline" (#173290). Separately, Piper 2.5.3 fixes a streaming bug on Piper's side: a plain `synthesize` after a text stream on the same connection was never answered. That is a Piper upgrade, not an HA one.

### What M15 (device control through HA) would gain

Conveniences and options, no prerequisite:

- 2026.11.0: expose many entities to voice assistants at once from the entities table. M15 keeps the exposed set small, so this saves clicks only.
- 2026.10.0: a Model Context Protocol card under Settings > System > AI. New MCP setups expose everything and allow administrator accounts only. That matters for design B (state reasoning), not design A.
- 2026.9.0, backward-incompatible: LLM tool names are prefixed with their integration (`HassTurnOn` becomes `intent__HassTurnOn`, `GetLiveContext` becomes `homeassistant__GetLiveContext`). Any M15 prompt that names HA's tools must use the new names. It also matters if either Ollama entry has an LLM API ("control Home Assistant") switched on; check that before the window.
- 2026.8.0: HA can use a local llama.cpp server or any OpenAI-compatible endpoint, or a LiteLLM proxy, as a conversation agent. Kronk already serves `/v1/chat/completions`. This is a future option for HA to reach Kronk without the Ollama shim, not something the upgrade forces.
- Matter (no Matter integration is loaded today): friendlier device setup (2026.6.0), sirens (2026.6.0), a network map (2026.9.0), and 2026.11.0 behaviour changes for concentration-sensor units and `climate.turn_on`. These only apply once Matter devices exist.

### What the upgrade puts at risk

- **Pucks' firmware pairing (ESPHome).** No firmware change is part of this upgrade, and none may be made (sprint guard rail). Notes touching ESPHome are about Bluetooth proxies (2026.6.0 makes Auto the default scanning mode; backward-incompatible, but the pucks use Bluetooth only at setup), serial proxies and the update list. 2026.7.0 bundles device updates into one card, so a single click can update all three pucks' firmware: do not click it. Risk: low. Check: the three `assist_satellite` entities back and idle, the six slot-2 selects unchanged (M12 H8).
- **The Ollama integration.** Not mentioned in the release bodies or blog posts read. The "All changes" lists, not read, carry six Ollama changes, and the `ollama` library moves 0.5.1 to 0.6.2. Risk: not known until those are read (corrected; this said "low"); the 2026.9.0 tool-name change is the one indirect item found (above). Check: the replay on `kronk-dev` and one spoken "Okay Nabu" request on production after the upgrade.
- **The conversation triggers the blueprint uses.** hassil moves from 3.5.0 to 3.12.1 (2026.6.3 alone carries 3.6.0 and 3.7.0; 3.12.1 in 2026.9.3), 2026.6 removes hassil's fuzzy matcher, and 2026.8.3 changes the conversation slot-list cache. hassil decides which sentences HA matches locally (`prefer_local_intents`) and which reach the Kronk music blueprint's sentence triggers. A different match moves a request between HA, the blueprint and Kronk. Risk: medium, and the one most likely to change behaviour silently. Check: the full corpus replay on `kronk-dev`, whose HA-local rows are checked read-only through HA's sentence-match debug, compared with the pre-upgrade baseline. The 2026.6.0/2026.7.0 trigger renames are for the Labs purpose-specific triggers, which Kronk does not use.
- **The Wyoming entries.** Three fixes, all on the satellite side of Wyoming (2026.6.2 announce protocols, 2026.7.2 no pipeline restart on error, 2026.8.2 error events). Kronk uses Wyoming for STT (Whisper on 10300, dev 10301) and TTS (Piper on 10200), not Wyoming satellites. Risk: low. Check: both pipelines run STT and TTS (a spoken request on each).
- **The debug-recording option M12 uses** (`assist_pipeline: debug_recording_dir`). No release note mentions it. Risk: low; but capture runs until 2026-12-01, and the HA restart cuts voice_tracer's correction windows short. Do the window after capture ends. Check: `scripts/voice_capture_check.py` and a recording appearing for the next request, if capture is still on.
- **Entity names (2026.11.0, backward-incompatible).** Entity names are now composed from the entity name and its device. Changed names keep the old name as a voice alias and in `friendly_name` "until the name is changed", and `friendly_name` "is going to be deprecated". tool_service's player list (`tool_service/main.py`, `_PLAYERS_TEMPLATE`) and the dev STT prompt (`scripts/build_stt_prompt.py`) read `friendly_name` of Music Assistant players. Risk: medium for player resolution ("in the kitchen"). Check: the replay's music rows, and `/music/players` names before and after.
- **Music Assistant integration against the pinned MA beta.** HA 2026.5.4 ships `music-assistant-client` 1.3.5 and `music-assistant-models` 1.1.115; 2026.11.2's `requirements_all.txt` has `music-assistant-client` 1.6.0 (corrected; this said the version was not known). MA stays on `2.11.0b5-kronk.9` (excluded). The runbook's H2 gives the pass criterion (the client's schema against MA's `min_supported_schema_version`). Check before the window: read the versions from the new image in a scratch container, and confirm the MA integration loads after the upgrade (the replay's music rows; `docker ps` shows MA was not restarted).
- **Authentication.** 2026.10.0 removes the auth provider's legacy mode (usernames normalised); 2026.11.0 tightens client-id checks for non-local addresses. Long-lived tokens (`HA_TOKEN`, `MA_TOKEN` is MA's own) are not mentioned. Risk: low. Check: `GET /api/` with `HA_TOKEN` answers 200; the mobile app still logs in.
- **Python dependencies (2026.11.0).** HA stops installing packages into `/config/deps`, for Core installs outside a virtual environment only. Container installs are not affected, and this HA has no `custom_components` (checked read-only).
- **The restart itself.** M12's runbook (stop with 120 s, recreate, H8 checks) applies. 2026.11 migrates entity names in `.storage` (one way), so rollback to 2026.5.4 needs the config volume restored from a backup taken before the start (corrected: this said the recorder would migrate its schema; `SCHEMA_VERSION` is 53 in both versions). M16 (backups) does not exist yet: the runbook says what to back up by hand.

## Other components, briefly

- **Grafana 13.2.4 to 13.3.1.** 13.3.0 and 13.3.1 fix a list of CVEs; 13.3.0's breaking change (a datasource API field) does not touch Kronk's provisioned dashboards. The monthly run takes the patch line meanwhile (13.2.5 now; 13.2.6 once it is 14 days old).
- **LiteLLM v1.88.1 to v1.110.0.** The release pages read (the newest 100 GitHub releases) reach back to v1.100 (corrected: this said v1.103); v1.89 to v1.99 were not read, and LiteLLM ships several releases a week. Items that touch Kronk in what was read: v1.103.0 "unregister logging callbacks removed from the stored config" (litellm/hooks.py is a callback), v1.103.8 a new image-signing key and a removed root CA. The monthly run takes v1.88.6 meanwhile. A major LiteLLM move needs the full changelog read by hand.
- **Piper 2.2.2 to 2.5.4.** 2.5.3 fixes the streamed-synthesis bug above. 2.5.1 disables ONNX Runtime telemetry, which onnxruntime 1.29.0 switched on ("piper was uploading trace events to Microsoft"). The running image has onnxruntime 1.23.2, so it is not affected, but any Piper upgrade must go to 2.5.1 or later (tenet 1). M20's TTS trial also touches Piper; order the two together.
- **nginx.** The pin `1.29-alpine` floats and runs 1.29.8, the last of the 1.29 mainline; newer lines exist up to 1.31.8. Proposal: pin an exact stable `1.30.N-alpine` as a deliberate change, after which the monthly run moves its patches.
- **llama.cpp.** Production units run b9585 (router) and b9611 (coordinator, devstral-q4); the newest build is b12498. Any build change re-runs the model benches; it is its own window.
- **wyoming-faster-whisper 3.1.0 to 3.9.0** (host venv with a ROCm ctranslate2 build). A rebuild, not a pin bump; it waits for its own window and the M13 measurements.
- **Python base images and uv.** `python:3.12-slim` floats; the cached base is 3.12.13 while 3.12.16 exists, and a rebuild does not pull. `pip install uv` is unpinned: the three running images have uv 0.13.9, 0.11.26 and 0.11.2. Both are code changes (pin exact versions), proposed, not done.
- **Python lockfiles.** The patch releases available are listed below (report only, see `docs/features/upgrade-cadence.md`). The OpenTelemetry instrumentation packages are pinned at a beta (`0.66b1`), which the rules do not compare; they move with the SDK by hand.
- **Music Assistant** is excluded (fork with the Pandora patch; upstream stable is 2.10.12, pre-release 2.11.0.dev builds). `docs/plans/MA_FORK_STATUS.md` (2026-10-16) records the upstream PR as not merged; the plan (2026-11-14) says it is not being pursued. Unchanged.
