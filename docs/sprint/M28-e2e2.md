## Rely on it

Yes for launching, checking and closing, with four things to know.

1. Do not kill a `launch`. If one dies, or answers a `herdr workspace
   create` error, look in `herdr workspace list` for the agent's name
   before anything else; the tool will not know that workspace (B3). The
   next `launch` of the name does refuse and names the label.
2. After a follow-up, use `wait --expect-commit` or read
   `report.changed_since_prompt`. Plain `wait` exits 0 at once on the
   first round's report. That is the ruling, not a fault, and it is the
   easiest way to read "done" wrongly.
3. `--expect-commit` and `agent_commits` rest on the coordinator's
   commits carrying `Claude-Session:`. They do here (8 of 8 in the last
   twelve commits, and `37595fa` live). A coordinator session that does
   not stamp makes its own commit count as the agent's (N13).
4. `prompt` goes by name. If a workspace was closed by hand and an agent
   of the name started by hand, `status` says `gone` but `prompt` reaches
   the other agent (N11). Read `status` before a follow-up.

Nothing found makes `status` or `wait` say done for the agent launched
when it is not, or miss `blocked` or `gone`, outside those four. Nothing
found closes a workspace the tool did not create. No write in the repo
and no git lock.
