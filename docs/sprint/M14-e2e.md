## Findings

1. **A messy "remember" statement is confirmed and not saved.** "Remember
   that we love Ulrich Schnauss. Thank you." is two sentences, so the gate
   sends it to the coordinator. In 8 of 8 runs (5 on the voice mount, 1 on
   each of the three mounts) the coordinator called no tool and answered
   "I have noted your preference for Ulrich Schnauss.", "Noted." or
   similar. With the gate switched off on the same build (3 runs) the
   `taste` rule sent it to the home agent, which called
   `remember_music_preference` every time (on dev the save is then refused:
   the taste file is mounted read-only). This is the one shape I found where
   the gate changes the outcome for the worse: before, the preference was
   saved; now the user hears that it was and it is not. The criteria do not
   cover it (criterion 5 asks only that the transcript reaches the
   coordinator), so it is not counted as a failure. It needs a ruling.
2. **One replay run claimed a skip with no tool call.** Replay run 1, row
   `eval-skip-treat-me-my-wallet-son` ("Skip.  Treat me my wallet son.",
   through HA on `kronk-dev`): `direct/messy`, no tool, spoken answer "I
   have skipped the current track. I do not have the ability to interpret
   your request about your wallet." (trace
   `f0b789eaaa16ee680e67cc65cc1128b4`). The row passed in the baseline, in
   the build's replay and in my rerun. Sent directly to the dev voice mount
   it called `control_music` in 18 of 18 runs with the gate on (12 with the
   corpus text, 5 with Whisper's leading space, 1 after the config test)
   and in 12 of 12 with the gate off, so 1 miss in 20 gate-on runs and none
   I can attribute to the gate: the route is the coordinator before and
   after. It is a coordinator miss on a row that is not on the known
   flapper list.

   anchored rules never matched them), so the gate changes only the rule
