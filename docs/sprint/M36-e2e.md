## tests/test_m21_pins.py (step 3)

Every pinned prompt variant is still checked for real. No fixture file
changed in 6317388; the hashes are the pre-M36 ones and the suite passes
against them.

- The system text hashed is the one the code renders today
  (`messages[0]["content"]`). For the variants that used to embed turns
  (the `ctx=1` renders and the pinned specialist's call in the pipeline
  scenarios) the test first asserts the turns arrive as chat messages
  between the system message and the task (`msgs[1:-1] == turns`), then
  appends the old block, built from the test's own constants, and hashes.
  The appended text is constant, so any change to a prompt, the facts
  block, the escalation text or the weather block still changes the hash.
- The variants without turns assert there are no messages between system
  and task, and hash the system text as before.
- Since the old hashes match, the removal of the block is shown to be the
  only change M36 makes to any system text.
- What it does not let through: a prompt change, a reordered or dropped
  turn, a turn written back into the system text.
- Note, not a fault: the `ctx=1` pins now equal the `ctx=0` text plus a
  constant, so they add no prompt coverage beyond the turn-order check;
  and the fixtures describe a block no code writes, so the next deliberate
  regeneration will change all of those hashes at once.
