## B1 (blocker). One journal line can be stored against two runs, and a run with no count takes a neighbour's line

`decide()` judges each row alone. `plan()` never checks that a line it
gives to one row is not also given to another, or is not already the
transcript of a row that has words. `tests/test_m30_backfill_e2e8.py`,
all four `xfail(strict=True)`; run with `--runxfail` to see each fail:

| Test | The house | What the script does |
|---|---|---|
| `test_a_run_with_no_count_does_not_take_the_transcript_of_a_run_seconds_later` | Run A on the kitchen puck, no stored count, nothing of its own in the journal. Run B on another puck three seconds later, with a count; its line is in the journal | Fills B, and **fills A with B's words** ("no stored count; the only transcript within 60 s") |
| `test_two_empty_rows_that_match_one_line_are_neither_certain` | A and B three seconds apart, the same count; the journal holds one line of that length (the other lost) | **Fills both** with the one line |
| `test_a_line_that_is_the_transcript_of_a_row_with_words_is_not_given_to_its_neighbour` | B has Tempo's words and "the journal agrees". A, three seconds earlier, empty, same count, nothing of its own | Reports `text R-B the journal agrees` and **fills A with the same line** |
| `test_a_gap_in_the_middle_of_the_journal_does_not_make_a_neighbours_line_the_only_one` | The journal has entries long before and long after (so it "covers" the run) and nothing for nine seconds round A's own line; a line of a run Tempo never held is 4.9 s after A's STT span. A has no count | **Fills A with the stray line**. Coverage is first entry and last entry only; a hole in the middle cannot be seen |

One unit serves every satellite, so two pucks that wake on the same
"Okay Nabu" are the plain way to get runs seconds apart. With both lines
present the script is right (two in the window, both left; D1 covers it).
It goes wrong only when one of the two has no line or no count.

The fix I would ask for (the fix agent's, not mine):

1. In `plan()`, after every row is judged: a line that is the one match
   of more than one row (rows to fill and rows with text alike, same
   unit) makes each of the empty ones `left`, reason "the transcript is
   in another run's window too". Neither is certain.
2. Drop the fill for a row with no stored count, or keep it only when no
   other row of that unit's kind has a window that overlaps its own and
   the line is not claimed (rule 1). The live record has two such rows
   and neither would fill either way, so dropping it costs nothing and
   removes the fourth case, which rule 1 cannot catch (the stray line
   belongs to no row). This departs from plumbing 2 as written, so it is
   the coordinator's ruling.

## Should fix

1. **The scan of the NAS runs inside the transaction with the lock
   held.** 4,030 files took 0.7 s on tmpfs, three system calls a file
   (12,104). Over SMB at a few milliseconds a call that is tens of
   seconds to minutes for an archive of that size; the live archive's
   size I did not look at (66 recordings are still local). The timer's
   exports give way for that long, and anything that writes the record
   waits five seconds and fails. The scan reads nothing from the record;
   it could run before `BEGIN IMMEDIATE`. The dry run does the same scan
   with no lock, so its wall time tells the coordinator what `--apply`
   will hold the lock for. If it is over a minute, use `--no-audio` for
   the words and join the audio in a second run.
2. **A dry run straight after a killed apply** says `FAILED: the record
   cannot be opened: attempt to write a readonly database` (exit 1): a
   read-only opener cannot roll back the hot journal. Harmless, and the
   next export clears it within a minute, but the message points the
   wrong way. Say "a write was interrupted; the next export or `--apply`
   repairs it".
3. **The window's slack is wider than the data needs.** Five seconds
   after the STT span is the audio join's number, for a WAV's mtime. The
   journal line sits at the span's end to within 10 ms on all 111 live
   rows. One second either side of the span's end would have matched the
   same 111 and closes most of the room B1 needs. Plumbing 2 names the two and five,
   so it is a ruling, not a bug.
