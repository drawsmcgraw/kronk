### For Drew's decision on production

**D1. The prompt weakens the M14 messy gate.** On the builder's 714 synthetic
speech rows (my 105-row rerun gave identical text on both ports), 33 rows
have a reference that routes `messy`:

| | No prompt (10300) | Prompt (10301) |
| --- | --- | --- |
| Routed `messy` when the reference is `messy` (33 rows) | 24 | 16 |
| Routed `messy` when the reference is not (681 rows) | 11 | 5 |
| Rows with fewer sentences than the reference | 23 | 37 |
| Rows with more sentences than the reference | 11 | 2 |
| Commas in all transcripts (references: 87) | 103 | 142 |

The comma-separated prompt makes Whisper join sentences with commas. That
removes 6 false `messy` routes and loses 8 true ones. Of the 14 rows the
prompt broke, 9 are this: `m13-0002-clean`, `m13-0002-room`
(inc-1108-anime-pop-wet-basement, `messy` → `music`: the multi-sentence
capture would have played), `m13-0055-noise10`, `m13-0055-room`
("Pause. Sonos. Move. Dirt." → "Pause, Sonos, Move, Dirt."),
`m13-0061-clean`, `m13-0080-clean` ("Stop. Stop." → "Stop, Stop."),
`m13-0089-clean`, `m13-0134-noise10`, `m13-0135-clean` (all `messy` →
`default`). Of the 20 it fixed, 5 are the same effect in the other
direction (`m13-0005-room`, `m13-0102-room`, `m13-0104-clean`,
`m13-0104-noise10`, `m13-0140-clean`: one request that the unprompted model
split in two). The net of 95 → 89 command-form errors hides a gate that
catches a third fewer multi-sentence captures. The build report gives the 9;
it does not give the 24 → 16. If the M12 clips show the same, the gate
needs to count commas, or the prompt needs another separator; the
full-stop separator the builder tried made it worse the other way
(command-form errors 29 / 34 / 50).

**D2. A player name replaced a command verb, twice.** `m13-0069-room` and
`m13-0087-room`: "Shuffle …" came back as "SHIELD, …" (`music` →
`default`). Both in the reverberant variant; 2 of the 30 rows whose
reference starts with "Shuffle"; the other 28 start with "Shuffle" on the
prompted instance too (one, `m13-0087-noise10`, is "Chuffle" on both
ports). No other prompt name was added to any speech row on either port.
This is the hazard the plan names, at 2 of 714 on synthetic speech, and it
comes from the players category, which the criteria ask for. Dropping
players from the prompt, or only "SHIELD", is a single-variable test on the
dev instance.

**D3. "Play" heard as "Place" is not a prompt effect.** The build report
counts 3 rows where the verb was lost with the prompt (`m13-0210-room`
"Playbook", `m13-0216-clean` and `m13-0226-noise10` "Place") and suggests
the words after the verb pulled toward the prompt. Counting both
directions: of 549 references that start with a command verb, the first
word is wrong on 61 rows without the prompt and 61 with it; 5 rows lose it
only with the prompt (the three above and the two "SHIELD" rows) and 5 only
without (`m13-0055-clean` "Paws", `m13-0204-noise10` "Plays",
`m13-0216-room` and `m13-0233-room` "Place", `m13-0234-room` "Lace"). Of
432 "Play …" references, 19 come back as "Place…" on each port. It is
Piper's "Play" in front of a name Whisper does not know, on either
instance. Not evidence against the prompt, and not for it.

**D4. "Kronk" on non-speech.** The only prompt name returned on the 40
non-speech clips, on 2 of 4 clatter clips: "Kronk, Kronk, Kronk, Kronk,
Kronk." and "Kronk, Kronk, Kronk." (`m13-hazard-clatter-1`, `-3`); both
route `default`, so on a puck they would go to the coordinator as a
request. Without the prompt the same clips return other words (the
unprompted instance gave 2 or 3 different texts in 3 runs of each), and 4
of its 40 non-speech transcripts route `messy`; with the prompt all 40
route `default`. No station, artist, room or player name came back on
non-speech. Text on a third clatter clip was " ." with the prompt.

**D5. A name that is a command word goes into the prompt unattended.**
Stubbed: an artist or station named "Stop", "Next", "Play", "Shuffle" or
"Pause" is kept as a bare word in the line (`Kronk, Kitchen, Office, Radio,
Shuffle, Stop, Next, Pause, Play, …`), the file is written, the dev
instance is restarted, exit 0. Each is listed in `command_word_names` in
the one log line the nightly service prints; nothing else flags it. The
criteria allow a command word that is part of a name if it is listed; a
name that is only the command word is the case the plan's hazard is about,
and at 04:00 the list goes to the journal, not to a person. None on the
live sources today (`command_word_names: []`, checked independently). A
station named exactly "Radio" stays "Radio".

### Observations

1. **The model loads at start, not on the first request.**
   `wyoming_faster_whisper/__main__.py` calls `await
   loader.load_transcriber()` ("Pre-loading transcriber") before it opens
   the server. Measured: the dev instance restarted at 00:59:03 UTC and had
   logged no transcription when I read it at 01:27 UTC; it held 1.867 GB
   GTT and 0.424 GB RSS. After 163 transcriptions: 2.071 GB and 0.684 GB.
   Wrong in: `docs/sprint/M13-build.md` sections 1, 5 and 7 ("loads
   lazily", "the first Hey Jarvis after a changed night pays the load"),
   `systemd/wyoming-whisper-dev.service` lines 8-10 ("a running but unused
   instance holds about 0.1 GB"), `README.md` line 445 ("on its first
   transcription"), `docs/features/voice-pipeline.md` ("loaded on the first
   transcription after a start"; "the model reloads on the next request").
   Consequences, both benign: the cost is held from the start, and the
   first Hey Jarvis after a nightly restart does not pay a load. It also
   means the start is when the Hub would be asked: the dev instance
   started three times with `HF_HUB_OFFLINE=1` and loaded from disk, with
   no Hub, error or traceback line in its journal.
2. **The restart guard is a name pattern.** `check_unit` accepts any
   `[A-Za-z0-9@_.-]+-dev\.service`. With the restart stubbed, 84 unit
   strings were tried through `main()` (an empty string means no restart
   was asked for). Refused, exit 2, nothing written:
   every form of production's name (bare, upper case, mixed case, leading
   or trailing space, trailing newline, NUL, trailing dot, `.socket`,
   underscore, globs `*`, `?`, `[e]`, two units in one string in either
   order, absolute and relative paths, `\x2d` escape, `;`, `&&`, `|`,
   `$(…)`, backticks, quotes, comma, braces, `~`, `>`), every llama unit,
   `homeassistant`, `kronk-memwatch.service`, `docker.service`, the dev
   unit's own path, and the dev name with any other suffix. Accepted, and
   handed to `systemctl --user try-restart`: `wyoming-whisper-dev.service`
   and ten names that are not the dev unit:
   `wyoming-whisper.service-dev.service`, `wyoming-whisper@-dev.service`,
   `wyoming-whisper@x-dev.service`, `wyoming-whisper.-dev.service`,
   `llama-gemma4-e4b-dev.service`, `homeassistant-dev.service`,
   `alias-of-production-dev.service`, `x-dev.service`, `.-dev.service`,
   `..-dev.service`. Also accepted when given as `--restart-unit=<value>`:
   `-Hsomehost-dev.service`, `-M.host-dev.service`, `--system-dev.service`,
   `--dev.service`, which `systemctl` would read as options (`-H` is "run
   on this host over SSH"); not run. On this host today no other user unit
   matches the pattern (`list-unit-files`: only
   `wyoming-whisper-dev.service`; the system unit
   `systemd-tmpfiles-setup-dev.service` is out of reach of `--user`) and no
   alias symlink exists, so the script can restart only the dev instance,
   which is why this is not under "Blocks". It would restart any future
   `*-dev.service` user unit, or production through an alias named that
   way. The brief asked for a guard that refuses every unit but the dev
   one; this one does not. Fix: compare with the one name, and put `--`
   before the unit in the command.
3. **What the script can write.** `--out` (any path the caller gives), and
   a sibling `<out>.tmp`, which is a fixed name: a file already there is
   overwritten and consumed. With `--out` a symlink, the link is replaced
   by a regular file and its target is left alone. Nothing else is opened
   for writing; one `subprocess.run` with a list, no shell.
4. **Atomic write holds.** 300 rewrites under a polling reader: the file
   was never missing and never partial. A rename that fails, or a write
   that fails half way, leaves the old file whole and a `.tmp` beside it;
   the script then dies with a traceback (exit 1) rather than a message.
   No `fsync`. The mutant that writes the file in place survives the tests.
5. **Names in the file.** Stubbed names with `"`, `\`, `$`, `` ` ``,
   `$(reboot)`, `${PATH}`, newline, CR, tab, NUL, NEL, U+2028, `%h`, `#`,
   `;`, `'`, `WHISPER_INITIAL_PROMPT="pwn"` and `x" \nEVIL=1\n"`: the file
   has four lines, systemd 257 itself (a transient unit with
   `EnvironmentFile=` on a scratch copy, printing its arguments) gives one
   variable and passes it as one argument, equal to my own reading of
   systemd's parser. A bidi override (U+202E) and a zero-width space pass
   through into the prompt. An emoji is kept. A name longer than the
   budget is skipped and the next tried; that includes a room, which the
   rule says is kept "in full" (a 5,000-character room name is dropped
   without a message). Case duplicates and NFC/NFD forms fold; "Beyoncé"
   and "Beyonce" are both kept. With 200 rooms the rooms take the whole
   budget (32 kept, no station, artist or player).
6. **Failures that exit by traceback.** `http.client.IncompleteRead` and
   `BadStatusLine` (a source that drops the connection mid-answer),
   `RecursionError` and `MemoryError` are not caught: exit 1 by an
   uncaught exception, old file untouched, no restart. Same for an output
   directory that does not exist. The effect is right; the message is a
   stack trace.
7. **Other edges of the script.** `--max-tokens 1` writes
   `WHISPER_INITIAL_PROMPT=""` and restarts the dev instance with an empty
   prompt, exit 0. `--max-tokens 5000` is accepted (315 tokens in my case);
   faster-whisper keeps the last 223. `--ha-url` and `--tool-service` take
   any host: with a stubbed fetch, `--ha-url http://example.invalid:8123`
   would have been sent the bearer token. The defaults are loopback and
   the installed unit passes neither.
8. **Scorer.** WER normalisation drops every non-ASCII letter: "Beyoncé"
   becomes `beyonc` (an error against "Beyonce"), "Sigur Rós" becomes four
   words. Digits and number words differ ("5" / "five"), as do "OK" /
   "Okay" and "AC/DC" / "ACDC". A command-form error is a different rule
   or direct call; a wrong name inside the same rule ("in the kitchen" /
   "in the office") is not one, by definition; WER carries it.
9. **A sheet saved with a byte-order mark is refused**
   ("not a labelling sheet"): the header reads `﻿sample_id`. Excel's
   "CSV UTF-8" writes one. Loud, but it will meet the labeller.
10. **A missing or 8-bit audio file ends a run with nothing written.** The
    result file is written once, at the end; a `FileNotFoundError` on row
    150 of 200 loses the 149.
11. **Undo instructions, read as the person who runs them.** A1 (`curl -X
    DELETE …/entry/01M7P1PQG3W0XAPSA5ZXJX5J65`), H1, H2, H3 are runnable as
    written. A2 is not: it is a description of a websocket call ("from
    inside the container … aiohttp … `<its twelve fields>`"), with no
    script to run and no UI path (Settings → Voice assistants → kronk-dev
    → Speech-to-text). In that picker both entities are named
    "faster-whisper". The ordered list in section 5 ("A2, A1, then H2 and
    H1") leaves out H3: with the timer left enabled and H1 undone, the
    04:00 run writes `dev-prompt.env` again. H3's undo is in the section 4
    table.
12. **Docs.** The feature doc's gotchas do not mention the comma effect or
    the "SHIELD" substitution; both are in the build report only.
    Otherwise the section reads true against the installed units.
13. **Times in the build report.** The Wyoming entry was created at
    00:42:58 UTC and retitled at 00:43:13 (HA's `created_at` /
    `modified_at`); `ws_read_after.json` is from 00:44:17; the unit was
    enabled at 00:42. The report says 00:47 to 00:49 and "enabled at 00:46".
    The builder's `dev-prompt` bench run started at 00:44:24.
14. **Both Whisper units log every transcript at INFO** to the user
    journal (documented in the feature doc). Production's journal holds
    1,526 such lines since 00:14 UTC, nearly all the bench's synthetic
    sentences. With M12's text switch in mind: household speech is in
    `journalctl --user -u wyoming-whisper` regardless of
    `TELEMETRY_RECORD_TEXT`. Not M13's doing.
15. **`192.168.1.179:1400`** is the one listener on a LAN address in `ss`.
    It is Home Assistant's Sonos integration (SoCo's event listener port,
    `EVENT_LISTENER_PORT = 1400`; Sonos config entry from 2026-05-23), not
    M13.
16. **Free memory sits on memwatch's warning line.** `free` reads 11.5 GiB
    with both instances loaded; memwatch warns under 12 GB only with PSI ≥
    0.5 %. It logged "free=11.9 GB below warn but PSI some avg60=0.00% <
    0.5% — not counted" once, at 00:54:27 UTC. Expect that line often.
