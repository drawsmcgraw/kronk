## What the hand-off does on the real registry

Rendered through Home Assistant's own template engine, read-only
(`POST /api/template` on loopback, a render). Method: the blueprint file is
loaded with PyYAML (`!input` kept as a marker), and every `variables:` value
up to `kronk_text` is rendered on its own, in file order, with the values
before it passed in the request's `variables` field. Each result is read back
the way `homeassistant.helpers.template` does (`strip`, `literal_eval`, text
kept unless the result is a list, dict, bool, None or a number that looks
like one). `trigger` is supplied as a mapping (`id`, `sentence`, `slots`,
`device_id`), the device id read from the registry through the same
endpoint. The default-player input is the kitchen player.

Sentence: the corpus row's, `Play the album Get a Grit by Aerosmith.`

| Satellite | kronk14 hand-off | kronk13 hand-off | blueprint's own-device rung | tool_service resolves the suffix to |
|---|---|---|---|---|
| kitchen voice pe | `… Aerosmith. in the Kitchen` | same | `media_player.home_assistant_voice_0ac919_pe_01` | the same player, "the Kitchen speaker" |
| satellite 1 (Office) | `… Aerosmith. in the Office` | same | `media_player.satellite1_d8d1bc` | the same player, "the Office speaker" |
| basement voice pe | `… Aerosmith. in the Basement Theater` | same | `media_player.home_assistant_voice_0ab117` | the same player, "the Basement Theater speaker" |
| no device (typed in Assist) | the bare sentence | same | none | the default |
| named target (`… in the office`, from the kitchen) | the sentence | same | n/a | the Office player |

All three real satellites take rung 2 and hand off the same text kronk13
does, now that fix 1 is applied. The resolver, offline, over the live player
list read once through `_players_template`, reaches the player the
blueprint's own-device rung picks, for all three. With the origin device key
(the dev path) it reaches the same three players.
