## The mark's definition on the corpus (scope 4)

Method. Facts built as `voice_tracer/main.py` builds them: `transcript`
only with the switch on; `kronk_rule` and `kronk_action` only for rows whose
corpus tier is `kronk`, from `routing.decide(text)`. Every pair on one puck,
the later run starting 5 s after the earlier one ended. Sweep: every ordered
pair of the 158 spoken corpus rows (24,806 pairs), text on and off. The
corpus has no "not that", no "louder", no light command and one timer, so 58
tester-written probe pairs cover those. The sweep weights pairs by the
corpus's make-up, not by how often the household says them: the counts show
which classes exist, not a rate.

### False marks

1. **A stop or a thumbs-down marks whatever ran before it.** `find_mark`
   never looks at what the earlier run did. Marked `stop`, text on and off:
   `Set a timer for 2 minutes` → `Stop!`; `Who is this?` → `Stop!`;
   `Is 98.6 a fever?` → `Stop!`; `Update the magicmirror` → `Stop!`;
   `Thumbs up.` → `Stop!`; `Set an alarm for 7 a.m. tomorrow` → `Stop!`;
   `play a game with me` → `Stop!`. Marked `rate_down`:
   `Set a timer for 2 minutes` → `Thumbs down.`; `What's playing?` →
   `Thumbs down.`; `Stop.` → `Thumbs down.`. In all, 30 distinct
   non-playback earlier sentences take a `stop` mark and 41 a `rate_down`
   mark. A wake-word false trigger (no transcript) followed by "stop" is
   marked too (probe). Stopping a timer's alarm, or stopping a long spoken
   answer, counts as a wrong action.
2. **Near-repeat marks two different requests once the sentence has four or
   more words and one differs** (ratio (n−1)/n ≥ 0.75 for n ≥ 4). Corpus:
   `put on some jazz` → `put on some aerosmith` (0.750, on the boundary);
   `Play French Dinner Radio on Pandora.` → `Play French Cafe Radio on
   Pandora.` (0.833); `Play Mushroom Jazz radio on the basement voice pe ma`
   → `play some jazz on the basement voice pe ma` (0.842; the six-word
   player name carries the match). Probes: "play the beatles in the kitchen"
   → "play the eagles in the kitchen" (0.83); "turn on the kitchen lights" →
   "turn off the kitchen lights" (0.80) and → "turn on the office lights"
   (0.80); "Set a timer for 2 minutes" → "Set a timer for 5 minutes" (0.83);
   "what's the weather" → "what's the weather tomorrow" (0.89).
3. **Not false:** "louder", "turn it down", "skip", "thumbs up" and "resume"
   after "play jazz" are never marked. `play jazz` → `play blues` (0.50) and
   `play some jazz` → `play some blues` (0.67) are not marked.

Near-repeat precision on the corpus: 21 of 24 distinct marked pairs are the
same request said again (54 of 60 ordered pairs).

### Misses

1. **Stops that are not the bare form.** 7 of the 13 stop-meaning corpus
   rows do not classify as `stop` even with text on:
   `Pause the basement voice pe ma` (HA answers; a player is named);
   `Pasta`; `Pause. Sonos. Move. Dirt.`, `Stop. Sonos move, derp.`,
   `Stop.  Stop.`, ` Pause.  Thank you.` (all four route `messy`; the
   coordinator calls `control_music`, and the mark does not read the tool
   call); `ask Kronk to pause` (`lead_in`). With text off, HA's own `Pause.`
   and `pause` are missed as well (documented), so 9 of 13. Only Kronk's
   bare `Stop!`, `Stop.` and `stop` rows mark without text.
2. **Corrections that are not routing forms** (probes): "no", "no not jazz",
   "that's wrong", "never mind", "cancel", "turn it off", "cancel the
   timer". By design (no new patterns).
3. **"Not that" through the blueprint hand-off with text off** ("not that in
   the kitchen", unjoined): not marked (build report, For Drew 6).
4. **Near-repeats under 0.75**, same request, not marked (corpus):
   `Play the album Destiny Waving by Ulrich Schnauss` → `… from YouTube
   music, in the kitchen` (0.727); `play some jazz in the office` → `ask
   Kronk to play jazz in the office` (0.714); `Shuffle my YouTube music
   playlist, Anime Bankers.` → `Shuffle the YouTube music playlist, anime
   bangers.` (0.714); `Update the magicmirror` → `update the mirror`
   (0.667); `What's playing?` → `what's playing on the kitchen` (0.667);
   `Play the Albo Daisies of the Galaxy.` → `Play the album Daisies of the
   Galaxy by Eels on YouTube Music.` (0.632); `Who is this?` → `What song is
   this` (0.571). Lowering the threshold does not separate them: the same
   band holds different requests (`play pink floyd on the blue group` →
   `play pink floyd on the sonos move`, 0.714). Distinct corpus pairs marked
   at each threshold: 0.60 → 86, 0.65 → 57, 0.70 → 40, **0.75 → 24**,
   0.80 → 15, 0.85 → 8, 0.90 → 6.
5. **Only the run just before is marked.** "play jazz", "skip", "stop": the
   stop marks the skip, not the play (probe).

### The near-repeat threshold (0.75, word level)

| Case | Behaviour |
| --- | --- |
| 1 word | Only an identical word is a repeat, and one-word controls (`skip`, `louder`) never count. `stop` → `stop` is marked `stop`, not `near_repeat`. |
| 2 words | Identical, or one word added (0.80: "play jazz" → "play jazz music", → "play some jazz"). One word changed is 0.50; dropping to "jazz" is 0.67. Neither is marked. |
| 3 words | One word changed is 0.67: not marked. One added is 0.86: marked. |
| 4 words and more | Any single changed word marks (0.75 at 4, inclusive; 0.80 at 5). At 8 words, two changed words mark. |
| Mishearings | `Pasta` → `Pause.` is marked `stop` with text on (the stop form, not similarity; ratio 0.00), not marked with text off. `Pause.` → `Pasta`: nothing. "play Portishead" → "play Portis head" (0.40): nothing. A one-word mishearing in a long sentence marks ("… Sonos Move Dirt." → "… Sonos Move Derp.", 0.88). |
| Repeat differing by a room | "play jazz in the office" → "play jazz in the kitchen" (0.80) is marked. The mark cannot tell a wrong-room correction from a second request for another room. |
| Repeat adding a room | Marks only when the first sentence has 5 words or more. "play jazz" → "play jazz in the kitchen" (0.57) and "play some jazz" → "play some jazz in the office" (0.67) are not marked; `Play toys in the attic by aerosmith` → `… in the kitchen` (0.824) is. |
| Punctuation, case | Ignored: `What song is this` / `what song is this` is 1.0. |

Window edges, as coded: a gap of 60.0 marks, 60.05 does not. A later run
that starts before the earlier one ended (barge-in) has gap 0.0 and marks.

**How the join is made.** For each recording, in sorted path order:
candidate runs have the same pipeline, the same device when both sides have
one, and the WAV's mtime inside `[run start − 2 s, run end + 5 s]`; the run
whose end is nearest the mtime wins; a run already taken is not reused. The
directory's monotonic name is not used at all, so a host reboot cannot
mis-join by itself (it only changes processing order). Both clocks are this
host's, compared as epoch seconds, so time zone and DST do not enter.

| Case (exact input) | Result |
| --- | --- |
| Same puck, A 0–20 s (WAV closed at 8.5 s), B 21–23 s (WAV at 22.9 s), both traced | Correct: A→A, B→B |
| Long Kronk answer 0–30 s (WAV at 9 s), "not that" 31–33.2 s (WAV at 33 s) | Correct |
| Two pucks, simultaneous runs, both spans carry a device id | Correct |
| **A has no trace**, A's WAV closed at 3.0 s; B runs 4.5–6.6 s, B's WAV at 6.5 s | **Wrong, silently**: A's audio gets B's run and transcript with no note; B's own audio is left `no trace` |
| Same, but B starts 2.5 s after A's WAV closed | Correct: A `no trace`, B→B |
| The wrong case again, but the later run has the smaller directory name (after a host reboot, or `99999999999` against `100000000000`: paths sort as strings) | Correct this time, because B's WAV is processed first. The outcome depends on processing order |
| A run with no device id on its span (a false trigger or STT error) is the only candidate while another puck's recording closes within its window | The other puck's audio is joined to that run; wrong only when the recording's own trace is missing |
| mtimes rewritten (`cp` without `-p`, `rsync` without `-t`, a restore) at a moment a household run happens | One recording joins that unrelated run; the rest `no trace` |
| Host clock stepped back 10 s between the run and the WAV close | `no trace`, not a wrong join |

So a wrong transcript can sit beside an audio file with nothing in the row
to show it, in one shape: the recording's own run is missing from Tempo,
and another run on the same pipeline (same puck, or a device-less span)
starts within 2 s after the WAV closed or ended within 5 s before it. The
cost is a false Whisper error in M13 if the bench scores `heard` against
`correct_text`. A check that would catch it: compare the WAV's duration
with the run's `voice.stt.listen` span.
