## Findings

### Blocker

**B1. The fresh-state note says each process's RAM is inside "Other used
RAM". It is not.** The note, new in this round, on `/dev/resources` with
`gpu_mem.json` fresh:

> Per-process segments are GPU memory (GTT + VRAM). Other used RAM is used
> RAM minus them: the system, caches, and each process's own RAM (the RAM
> figure on its card).

The page's own figures at 17:07:25 contradict it. "Other used RAM — 29.0
GiB". The RAM figures on the five cards: 8.2 + 9.9 + 14.9 + 0.63 + 0.62 =
34.2 GiB. A 29.0 GiB segment cannot hold 34.2 GiB.

Why: the card's RAM figure is the process's RSS, and RSS counts the pages
of a memory-mapped file. Those are page cache; the kernel counts them as
available, so they sit in the bar's "Available" segment, not in used RAM.
Read on the host at 17:10:34:

| process | GPU memory | RAM on its card | anonymous | file-mapped | shared |
|---|---|---|---|---|---|
| llama-devstral-q4 | 34.01 | 8.20 | 8.02 | 0.17 | 0.00 |
| llama-gemma4-e4b | 5.10 | 9.87 | 8.39 | 1.48 | 0.00 |
| llama-talkie | 0.01 | 14.90 | 1.62 | 13.21 | 0.07 |
| wyoming-whisper-dev | 1.93 | 0.63 | 0.30 | 0.16 | 0.16 |
| wyoming-whisper | 1.93 | 0.62 | 0.30 | 0.15 | 0.16 |
| sum (GiB) | 43.0 | 34.2 | 18.6 | 15.2 | 0.4 |

`/proc/meminfo` at the same moment: total 122.8, available 51.3, used
71.5, `Cached` 40.6 GiB. Used minus GPU memory is 28.6 GiB.

So Talkie, the case the first test's S2(b) was written about, has 1.7 GiB
in "Other used RAM" and 13.2 GiB (its model file, mapped) in "Available".
The note is wrong about it by 13 GiB. "caches" is wrong the same way: 40.6
GiB of page cache is nearly all in "Available".

Where it came from: the first test report said "Talkie holds 15.4 GiB of
RAM, which the bar counts inside System / other", and the ruling sent
that to the fix. The fix agent wrote on the page what it was told. The
premise was not checked against the host by the first tester, the
coordinator, or the fix agent.

Same sentence, same error: `docs/features/resources-live-memory.md`
("the system, caches, and each process's own RAM") and the comment above
`MEM_BAR_LABELS` ("which holds each process's own RAM").
`tests/test_m25_fix1_pages.py` pins the wrong text
(`"each process's own RAM" in f["note"]`).

Graded blocker by the brief's line: a label that says something untrue in
a state I rendered. It is the state the page is in every day. The labels
themselves ("<name> GPU memory", "Other used RAM") are true, the
arithmetic is right, and the fix is a sentence: say what the segment is
(used RAM minus the listed GPU memory) and do not say what is in it, or
say that a card's RAM figure includes mapped model files and need not fit
inside it.
