## Findings

### Blocks installing the timers

**N1. A recovery acts on an old record without looking at what changed
since.** `_recover_one` (`scripts/upgrades.py:2009`) reads any production
tag other than the recorded previous one as "the new version runs
unverified" and finishes "the rollback" by deploying the recorded previous
tag. It never compares with the tag the run made (`intent.tag`).

- Input (fake house, real git): litellm `v1.88.1 -> v1.88.6`, the run
  killed during verify; the next day a person tags `sprint-Y` at HEAD and
  deploys it (`deploy_tag.sh deploy` is not refused: the lock died with the
  run, and nothing told anyone a run was interrupted); then the next run.
  Result: `mutating=[('deploy_tag', 'deploy', 'sprint-X')]`, production
  moves from `sprint-Y` back to `sprint-X`, notice `Kronk upgrade: an
  interrupted run was recovered (litellm)` / `recovered: finished the
  rollback: v1.88.1 runs again, git has v1.88.1 (interrupted at step
  verify)`. The notice does not name `sprint-Y`.
- The same with `sprint-Y` made before the pin commit (litellm already runs
  `v1.88.1`, nothing is ahead): `sprint-X` is deployed over it all the
  same. The same two cases with the run killed before its deploy (step
  `deploy`): same result. Four of four.
- Telemetry and Home Assistant: the recovery's `up -d` is made without
  `compose config --hash` and without the bind-mount check. Input: grafana
  killed during verify; before the next run the config hash no longer
  matches and a provisioning file is newer than the container. Result:
  compose calls `[('up', '-d', '--no-deps', 'grafana')]` only; `recovered:
  finished the rollback`. The guard's own words for that state are "a
  recreate would load it unreleased".
- Mutant `i6` (the production-tag clause removed) survives the suite: no
  test covers this line either way.

**N2. A failed `docker inspect` is reported as "does not exist" and, for
Home Assistant, "Home Assistant is down".** `what_runs`
(`scripts/upgrades.py:1723`) treats any non-zero `docker inspect` as a
missing container. Input: `docker inspect` failing from one point on (a
timeout, a daemon restart), Home Assistant running `2026.5.4` throughout.
Result: `Kronk upgrade: 1 not applied: Home Assistant is down` /
`homeassistant 2026.5.4 -> 2026.5.5: not applied; git is at 2026.5.4 again
