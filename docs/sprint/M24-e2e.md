## Method

- **Old against new.** A harness ran in a scratch worktree of each tree
  with LiteLLM replaced by an `httpx.MockTransport` (no socket), the clock
  frozen. It recorded every request body sent to the model and every
  response body. 1,134 cases: every route (`direct` and the six agents)
  forced, on the four mounts, streamed and not, `VOICE_STREAM` on and off,
  under six model behaviours (answers and stops; stops with
  `finish_reason: length`; every call 500; first call 500; first call a
  connection error; first call 400), with three sentences of mine each.
- **Mutants.** 32, each in a scratch worktree, the full suite run on each.
- **Live.** 50 Talkie requests and 20 ordinary ones on the dev routes, one
  at a time, each matched to the orchestrator-dev event log by time window.

### Should-fix

1. **The installed Talkie unit is not the repo's (criterion 3).** Comment
   lines only; `ExecStart` is identical. The coordinator's step, as in the
   build report: copy the file, `systemctl --user daemon-reload`, no
   restart.
2. **A capped reply can be dropped whole.** `unfinished_tail` drops the
   tail whenever at least one complete unit comes before it, and a blank
   line or a heading counts as a unit. Through the app on the speech mount,
   model faked, `finish_reason: length`:

   | Talkie's text | Spoken |
   |---|---|
   | `"\nThe kings were William I, William II, Henry I, Stephen, Henry II"` | `""` (nothing) |
   | `"Certainly:\nThe kings were William I, William II"` | `"Certainly:"` |
   | `"Kings of England\n\nWilliam I, William II, Henry I, Steph"` | `"Kings of England."` |
   | `"The kings were William I, William II"` | the whole text (as designed) |

   Same with `VOICE_STREAM` on and off. Not seen live: 0 of 50 Talkie
   replies began with white space, and the 4 capped ones ended on full
   sentences. The cost when it happens is a silent or one-word spoken
   reply with no error. The design's own rule ("a reply with no complete
   sentence is kept as it is") should hold for these.
3. **No test pins that `llm.stream` hands the cap to `_stream_body`.**
   Mutants M03 and M04 below survive: with either, the cap never reaches
   the model in that lock mode and the suite is green. The builder's tests
   patch `agents.llm.stream` whole or call `_stream_body` directly. It does
   work live on dev (`MODEL_LOCK=server`: four `reply_capped` events,
   `max_tokens: 120`). `MODEL_LOCK=pipeline` is covered by nothing.
4. **The cap's comment is not on `/settings`.** Scope 3 asks for "a value
   on `/settings`, with a comment". `/dev/api/settings` shows
   `max_reply_tokens.talkie`, value 120, `source: "code default"`,
   `comment: null`, because the live config directories do not carry the
   key. The builder's "Left for the coordinator" item 3 closes it.
