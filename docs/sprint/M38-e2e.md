   dot.** `/message`, `/history` (including the DELETE that clears it),
   `/files` and `/api/status` are absolute paths in `index.html`.
   Someone typing on `/dev/` reaches production's orchestrator every time.
   This predates M38 and isn't in its scope. The build found only the dot.
   It's for the coordinator to admit or drop (`feedback_backlog_admission`:
   it matters for any test that uses "the chat page on dev").
2. **`upgrade_rules.toml` line 291 reads `/api/status`.** That's the
   nginx component's health check after a patch upgrade, and it isn't in
   M38-criteria's caller list. Under the ruling, a model server down (or
   the props file stale) now fails that check too, after its 300 s of
   retries, and rolls nginx back for a reason unrelated to nginx.
   Today the run skips nginx (its pin `1.29-alpine` floats), so the check
   never runs. When nginx is pinned exactly, the check may want
   tool_service/LiteLLM only, or the operator accepts the stricter
   reading.
3. Health lags a stopped server by up to the props timer's 60 s. That's
   accepted in the Rulings and not re-tested.
4. Model behaviour seen in passing, not this item: one answer opened with
   "I am using the pre-fetched data for the home location." In criterion
