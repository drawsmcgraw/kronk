## Blocker

### B1. The guard no longer sees a write of the live record, or its deletion

`tests/conftest.py`, `_voice_changes_not_the_timers`. A change is taken
for the timer's when the file's mtime falls in one of the timer's runs.
But the timer writes three of the guarded files on every run: the record
and both status files (seen with `stat`: record 01:35:43.991, statuses
.993 and .994, the unit's run 01:35:43.893 to 01:35:44.006). So:

1. **A test's write of any of the three is hidden by the timer's next
   run**, at most 60 s later. The build report names a 0.1 s window; the
   real one is the whole run but its last minute. For the status files the
   harm heals itself. For the record it does not: a row a test inserts or
   deletes stays, in the file that is backed up.
2. **A test that deletes the record passes at any moment.** For a file now
   gone the guard uses the old mtime, and the record's old mtime is always
   the timer's last run before the session.

Shown on a scratch copy of the tree (`git archive HEAD`), `HOME` in
scratch so both the record's path and `data/` were scratch, the real
journal of the live unit, one test per session:

| What the test did | Guard | pytest exit |
|---|---|---|
| wrote `data/voice_runs.json` 5 s after a timer run | `FAILED: the test run changed the live voice-run record or its copies: …/tree/data/voice_runs.json` | 1 |
| inserted a row into the record; the timer's next run then touched it (stand-in: the scratch record's mtime set to the live status file's new mtime at that instant) | silent | 0 |
| deleted the record | silent | 0 |

The first line is what the brief asked for and it holds: with the timer
running, a hand write between runs still fails the run. The suite passes
with the timer live (twice, three or four timer runs inside each).

What the fix needs is the coordinator's to choose; mtime alone cannot do
it. Two that would: compare something only a test would change (the
record's row count and `max_seq` against what the journal's "new N,
changed N" lines account for), or make the write impossible instead of
detected (the suite already points `KRONK_VOICE_DB` at scratch; a session
fixture that fails any `open` or `sqlite3.connect` of the live paths).
Two strict `xfail` tests state the two holes
(`tests/test_m30_heard_e2e6.py`).
