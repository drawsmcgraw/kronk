### S1: what was tried

A fake `docker` on `PATH` in scratch (logs its arguments, answers the three
calls, archives a 21-member source tree with the host's `tar`). Each case
runs in a fresh sandbox holding a non-empty `real/` (a `notes.txt` and an
old `lib/libroctx64.so.4.1.70200` with content `OLD`) and an empty
`empty/`. For each: exit status, number of docker calls, and a listing of
the whole sandbox (type, mode, link target, the two files' content) before
and after.

Refused with exit 2, no docker call, nothing changed (the message names
the path given and what it resolved to):

- `real` named directly, absolute and relative; `real/`, `real/.`,
  `//real///`; `.` from inside it; `..` from inside `real/lib`.
- A symlink to it: relative link, absolute link, a chain of three links,
  the link with a trailing slash, a link named with a space, a symlink at
  a middle component (`mid/sub` where `mid -> real`).
- `..` forms: `real/new/..`, `real/a/b/../..`, `./real/new/..`,
  `link/../../real` (the link points two levels down, so the physical
  `..` lands elsewhere than the logical one), `other/x/up/lib/..` where
  `up -> ../../real`, `real/afile/..` where `afile` is a file,
  `real/self/self/self` where `self -> .`.
- A file where a directory is expected (`afile`, a symlink to it:
  "exists and is not a directory"; `afile/sub`: "its parent directory …
  does not exist").
- A missing parent (`nope/x`); `/` and `/..` ("refusing /").
- A directory holding only a hidden file; one holding only an empty
  `lib/`; a directory named with a space; `./-d`.
- A directory that cannot be read: mode 000 and mode 300 (write and
  search, no read) both give `find: … Permission denied` and "cannot
  read", exit 2. Mode 600 (no search) and a parent of mode 300: refused
  as not empty. A symlink reached through a parent without read
  permission: resolved and refused.
- The empty string, `-d`, `--`, two directories, `--image` with no value:
  usage, exit 2. A literal `~/services/rocm-7.2` (unexpanded): refused,
  no parent.
- A symlink loop: `realpath: … Too many levels of symbolic links`, exit 2.

Seven of these were repeated with GNU coreutils 9.5 first on `PATH`
(`realpath`, `readlink`, `sort`, `sha256sum`; this host's defaults are
uutils 0.2.2): same results, except the loop (T3).

On the real extraction in scratch (1.9 GB, non-empty by then),
`build <link-to-it>` and `build <it>/new/..` were both refused, exit 2.

Accepted, and right to be: an empty directory; a path that does not exist
whose parent does; a dangling symlink (the build creates the link's target
and fills it, including when the target is a new name inside `real/`).
That last one is the resolve-first rule applied to a link whose target is
missing; it writes only into a directory it has just created.

### T1. Swapped after the check

The fake docker's `image inspect` runs after the emptiness test and before
`mkdir`, so a hook there stands in for a second process:

- `empty/` replaced by a symlink to a non-empty directory that has no
  `lib/`: the build extracts into that directory beside its files, writes
  `MANIFEST`, exit 0. The same when the path did not exist at the check
  and a symlink appears there, and when a file appears in the empty
  directory (it is left beside `lib/`, and `verify` passes: N5).
- `empty/` replaced by a symlink to a directory that **has** a `lib/`
  (the shape of `~/services/rocm-7.2`): `mkdir: …/lib: File exists`,
  exit 1, nothing written. The plain `mkdir` the fix put in place of
  `mkdir -p` is what stops it; with `mkdir -p` restored the old library
  is overwritten (run as a mutant, T6).
- `lib/` itself replaced by a symlink to another `lib/` between `mkdir`
  and the extraction (hook in the fake's tar call): the old library there
  is overwritten; the build then fails at `check_extracted` ("a symlink
  points outside its directory"), exit 1.

All three need a process with write access to the destination acting
inside a window of about a second. Nothing on this host does that, and a
shell script cannot close it fully. Not an ordinary path; note only.

### T2. A trailing newline in the path

`dir=$(realpath -m -- "$given")` loses trailing newlines. `build $'d\n'`
with a non-empty directory of that name and an empty `d` beside it fills
`d`, exit 0. The other direction is safe: `build $'real\n'` is refused as
`real`, non-empty. The check and the write always use the same resolved
path, so no non-empty directory is written into; the build can land in a
directory other than the one named.

### T3. Late failures

A read-only empty directory, or a destination under a parent that cannot
be searched, passes the checks (nothing readable says it is not empty, or
`[ -e ]` is false) and fails at `mkdir` with `mkdir: Permission denied`,
exit 1, after two docker calls. Nothing is written. With GNU `realpath`
first on `PATH`, a symlink loop takes the same road (`realpath -m` prints
the path unresolved; `mkdir: Already exists`, exit 1); uutils `realpath`
refuses it at once. The header gives exit 1 as "verify found a difference,
or the extraction did not match the list".

### T5. Backslash in a name

`sha256sum` (uutils and GNU alike) marks a name holding a backslash by
putting a backslash before the hash, and the script keeps it:
`a\b<TAB>f<TAB>664<TAB>1<TAB>\2d71…`. It is the same for build and verify
and no listed member has such a name. Cosmetic.

  Equivalent here.
